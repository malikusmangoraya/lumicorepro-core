## 33. REFERENCE INTELLIGENCE / DESIGN BENCHMARKING

When the prompt cites a brand reference or design benchmark (e.g. "Apple-style product clarity", "Aesop-style editorial restraint", "Stripe-style UX"), never copy the reference. Decompose it into design attributes, then build an original design system from those attributes.

Reference → decompose into:

- **Typography characteristics** (weight, scale, case, tracking, width)
- **Spacing characteristics** (density, rhythm, white-space philosophy)
- **Navigation behavior** (menu style, header weight, wayfinding)
- **Image treatment** (lighting, composition, crop, color grade, subject framing)
- **Motion principles** (easing, duration, what moves vs what stays still)
- **Content density** (sparse vs information-rich, pacing)
- **CTA hierarchy** (one dominant action vs distributed actions)
- **Interaction patterns** (hover/link/button/card behavior)
- **Brand emotion** (the feeling the reference evokes and why)

Then synthesize an **original** design system that carries those attributes without resembling the reference. Document the mapping in the project brief (which attribute came from which benchmark, and how it was translated). Criteria: distinctiveness beats resemblance — passing the benchmark is having its qualities, not its look.

## 10. VISUAL CRITIC

Act as a senior art director. Score: composition, typography, color, hierarchy, spacing, imagery, consistency, originality, visual storytelling, brand fit.

Do not judge by taste alone. Judge against concrete, verifiable checks per category:

- **Hierarchy:** is there one clear visual focal point per section? Do headings scale logically (H1→H2→H3)? Is the primary CTA the visually dominant action?
- **Whitespace:** is spacing intentional and consistent with the design token scale (not random padding)? No cramped or floating orphans.
- **Typography:** is type paired coherently (max 2-3 fonts)? Are weights/sizes matched to hierarchy? Noto line-length/measure, no awkward line breaks, no font soup.
- **Composition:** is each section balanced (centered/symmetry or deliberate asymmetry)? No accidental misalignment, no orphaned elements.
- **Brand distinctiveness:** "If the logo is removed, does this still feel like a unique brand?" — the design must carry the brand alone.
- **CTA prominence:** the primary action must be instantly findable without scrolling effort or squinting.
- **Repeated patterns:** identical card/grid/section formulas reused without purpose count as failure, not consistency.

Give a pass/fail verdict per category with the concrete evidence behind it. Identify weak areas. Do not praise the site merely because it has many effects.

## 11. UX CRITIC

Act as a senior UX designer. Evaluate: clarity, navigation, discoverability, task completion, interaction feedback, information hierarchy, mobile UX, error recovery, friction, accessibility. Score each category.

---

## 12. CONVERSION CRITIC

Evaluate: value proposition, CTA clarity, trust, social proof, objections, friction, urgency when appropriate, product demonstration, purchase/request flow. The primary CTA must be obvious.

---

## 13. ANTI-GENERIC CRITIC

Check: repeated section patterns, repeated card styles, excessive glassmorphism, excessive gradients, generic copy, excessive glow, meaningless 3D, unnecessary particles, template-like hero, weak brand identity.

Ask: "If the logo is removed, does this still feel like a unique brand?" If not, redesign.

## 14. MULTI-CRITIC REVIEW

Run conceptual review roles:

- **Visual Critic** — visual quality and originality
- **UX Critic** — usability
- **Conversion Critic** — business effectiveness
- **Accessibility Critic** — inclusive usability
- **Performance Critic** — loading and runtime quality
- **Security Critic** — security
- **Final Reviewer** — final release decision

Each critic reports: score, issue, severity (P0-P4), suggested fix.

**Independence rule:** the builder/implementer must never grade their own work as the reviewer. Reviewers judge only the actual artifacts — rendered screenshots, live DOM, measured network timings, console logs, axe/audit output — never from memory or assumption. If a critic cannot point to the artifact evidence behind a pass, the pass is invalid and must be reported as "not verified".

---

## 15. ISSUE PRIORITY

Use: P0 = blocking, P1 = critical, P2 = high, P3 = medium, P4 = minor.

Never ship unresolved: P0, P1.

---

## 16. SELF-HEALING LOOP

When an issue is detected: DETECT → CLASSIFY → LOCATE → FIX → BUILD → TEST → VERIFY.

Never modify randomly. Always make the smallest effective fix. If a fix creates another issue: ROLL BACK OR CORRECT → RETEST.

**Regression detection is mandatory after every fix:** a fix must never be accepted on the basis of the single failing condition alone. After each fix, re-run the full relevant verification across all affected breakpoints and interaction paths (e.g. a CSS fix for one viewport must be re-screened across 375/768/1024/1440/1920 and reduced-motion). Before/after evidence (screenshots or measurements) must be compared; any new breakage introduced by the fix is itself a bug to fix or roll back.

---

## 17. FAILURE PROTECTION

If repeated failures occur, do not endlessly loop. After 3 meaningful failed attempts on the same issue: STOP THAT REPAIR LOOP.

Generate: issue, attempted fixes, failure reason, affected files, recommended manual action. Never pretend that the project passed.

## 19. DESIGN TIERS

- **STANDARD:** usability, clean design, responsive behavior, speed, maintainability.
- **PREMIUM:** add stronger visual identity, refined typography, custom motion, richer imagery, better interaction, stronger content hierarchy.
- **SIGNATURE:** add where appropriate custom storytelling, advanced interaction, immersive visual direction, custom transitions, interactive 3D, editorial layouts, high-end micro-interactions.

**Signature is genuinely different, not just more animation.** Premium ≠ "same layout with more effects". Signature must change the design language itself, individually or in combination:

- **Custom layout:** editorial / bento / asymmetric art-directed composition — not the standard hero→features→pricing grid.
- **Storytelling:** the page has a narrative arc (scene to scene), not a disconnected feature list.

- **Interaction:** brand-specific interactions (scroll-driven story, custom transitions, micro-interactions) that nothing else could substitute.
- **Brand-specific visual language:** the moment of recognition comes from the design itself; removing any three decorative elements must still leave the language intact.

Signature does not mean more decoration. Signature means more craft.

## 3. INDUSTRY PLAYBOOK ENGINE

Instead of designing from zero every time, the agent picks a per-industry playbook. Supported industries: ecommerce, marketplace, saas, automotive, food, fintech, portfolio, education, healthcare, real-estate, electronics, industrial, hospitality, entertainment, sports, fashion.

Each playbook defines:
- strategy (primary goal, business model)
- ux (patterns, journeys, mobile priorities)
- pages (which pages: home/category/product/cart/checkout/account/)
- components (critical ones: search, filters, product_card, cart_drawer, wishlist, reviews)
- conversion (primary CTA, secondary CTA, trust signals)
- content (headline formulas, product copy, FAQ)
- visual (density, imagery, typography, motion, 3d, cta style)
- qa (what must be tested for this industry)

Example — E-commerce playbook:
```yaml
industry: ecommerce
primary_goal: purchase
pages: [home, category, product, cart, checkout, account]
critical_components: [search, filters, product_card, cart_drawer, wishlist, reviews, recommendation]
conversion:
  primary_cta: buy_now
  secondary_cta: add_to_cart
trust: [reviews, shipping, returns, payment_security]
mobile_priority:
  search: high
  filters: high
  sticky_cart: high
```

**Per-industry visual strategy** (different sites must behave differently):

| Industry | density | imagery | typography | motion | 3d | cta |
|----------|---------|---------|------------|--------|-----|-----|
| Automotive | low | cinematic | editorial | slow | conditional | concierge |
| Food | medium | high | friendly | energetic | optional | order |
| SaaS | medium | product UI dominant | clean | subtle | rare | start_free |
| Fintech | medium | restrained | trustworthy | restrained | no | fixed/term |
| Luxury real-estate | low | large editorial | refined | slow | yes (tours) | book_viewing |

**UX anti-patterns (avoid):** hidden_pricing, excessive_modal_usage, weak_search, unclear_checkout, fake_reviews, vague_cta, unnecessary_carousels.

## 4. BRAND PLAYBOOK ENGINE

Brand archetype playbooks (luxury, minimal, futuristic, editorial, playful, corporate, bold) add the "feel" layer:

- visual personality (3-5 adjectives)
- typography behavior (voice via type)
- spacing philosophy
- motion character
- color behavior (restrained vs vivid, tolerance for gradient/surface effects)
- imagery treatment (photographic style)
- interaction style

**Merge rule:** `INDUSTRY PLAYBOOK + BRAND PLAYBOOK + USER REQUIREMENTS + REFERENCE ATTRIBUTES` all merged → one final design direction. Example: "Premium luxury automotive website" → AUTOMOTIVE (cinematic, editorial, concierge CTA) + LUXURY (exclusive, confident, refined, restrained color) + user requirements + reference traits.

Connects every upstream system into one deterministic design specification.

Flow:
```

 ↓

 ↓
```

Output (machine-readable spec the generator builds against — never invented per file):

The engine merges: USER REQUIREMENTS + BUSINESS ANALYSIS + AUDIENCE + BRAND + REFERENCE ATTRIBUTES + INDUSTRY PLAYBOOK + BRAND PLAYBOOK + PERFORMANCE CONSTRAINTS + ACCESSIBILITY REQUIREMENTS → single design specification.

---

## 6. CONSTRAINT RESOLVER

When requirements conflict, resolve explicitly per device/context instead of ignoring one side.

- "Ultra-premium, lots of animation, super-fast mobile" → desktop: rich motion; mobile: simplified motion; reduced-motion: minimal motion.
- "Lots of products + minimal design" → reduce visible products, introduce filtering, use progressive disclosure.
- "Trust-critical finance + decorative effects" → decorative effects removed, data visualization prioritized, motion restrained.

Every resolved conflict must be recorded in the design manifest.

## 7. DESIGN MEMORY / DESIGN MANIFEST

Every project writes a machine-readable `design-manifest.json` so later requests ("change the homepage hero") modify the existing system instead of re-deriving it.

```json
{
  "brand": { "archetype": "luxury", "personality": ["exclusive", "confident", "cinematic"] },
  "visual": { "density": 0.32, "motion": 0.45, "3d": true },
  "typography": { "heading_style": "editorial", "body_style": "modern_sans" },
  "colors": {},
  "spacing": {},
  "components": {},
  "constraints_resolved": [],
  "reference_sources": []
}
```

Per-stage artifacts (`.artifacts/01-business.json … 14-deployment.json`) make every decision traceable: `01-business → 02-audience → 03-brand → 04-reference → 05-playbook → 06-ux → 07-design → 08-architecture → 09-build → 10-designlint → 11-visual-score → 12-critic-review → 13-qa → 14-deployment`. A bug becomes "what design decision caused it, and where", not a blind re-roll.

| Visual density | 7/10 |

After implementation, capture Playwright screenshots (`desktop.png`, `tablet.png`, `mobile.png`) and evaluate the actual site against those targets:

- **Typography:** heading hierarchy, paragraph width, density, consistency
- **Brand:** colors, imagery, personality, originality

A lint pass for design, like ESLint for code. Rules:

| Code | Rule |
|------|------|
| DL001 | Hero heading too wide |
| DL002 | Primary CTA has insufficient contrast |
| DL003 | More than 4 identical cards |
| DL004 | Section spacing inconsistency |
| DL005 | Too many rounded containers |
| DL006 | Too many gradients |
| DL007 | Repeated decorative effects |
| DL008 | Heading hierarchy broken |
| DL009 | Mobile hero too tall |
| DL010 | CTA buried below fold |
| DL011 | Visual density too high |
| DL012 | Empty section detected |
| DL013 | Generic placeholder copy detected |
| DL014 | Repeated animation pattern |

Output format (severity + code + message):

Findings feed the self-healing loop (Part 2 §16): DETECT → CLASSIFY → FIX → BUILD → TEST → REGRESSION → SCREENSHOT.

## 12. REDESIGN AUTHORITY

If visual quality is below the target, do NOT patch only.

The agent is authorized to redesign: hero composition, section order, spacing, card structure, typography scale, CTA placement, interaction model, visual treatment — provided core user requirements remain satisfied.

A project never passes "because it compiles or has no console errors". A project is complete only when technical QA + UX QA + visual QA + design score all meet the required threshold.
